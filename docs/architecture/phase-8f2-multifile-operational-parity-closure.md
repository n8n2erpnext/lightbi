# Phase 8F.2 Multi-File Operational Parity Closure

## Boundary

This closure verifies the production path from authentic multi-file import to
canonical understanding, business-perspective selection, explicit source
evidence, governed full-file execution, chart presentation, and deeper BA
analysis. It does not authorize a generic six-source join or operational
decision use.

## Controlled architecture corrections

The existing canonical candidate layer already recognized the six sources
correctly. The missing bridge was relationship-aware document identity
presentation. A per-source suggestion could choose `InvoiceNo` on Accounting
while Sales and Accounting shared the canonical `OrderID` identity. The review
surface now projects the unique shared document candidate for the active
governed bundle. It remains non-authoritative until the user explicitly accepts
it.

A multi-source relationship that fails identity, period, currency, grain, or
cardinality validation now stays in the review surface with its exact blockers.
It no longer transitions to an active dataset that exposes a misleading
source-local Investigate action.

Investigation auto-preview is now safe under React Strict Mode. The session is
marked as auto-run only when the surviving timer starts, so the development
lifecycle cannot cancel the timer after prematurely consuming the run.

The legacy result card also has a defensive blocked-state presentation. A
missing governed handoff can no longer crash while reading chart/template
fields that do not exist on a blocked result.
