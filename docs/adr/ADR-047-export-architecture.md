# ADR-047 Export Architecture

Status:
Accepted

Context:
In many applications, exporting a CSV or PDF is treated as a generic, fire-and-forget file download triggered from a UI component. This breaks lineage. If a user receives an Excel file with critical financial data, they must be able to trace exactly which dataset, view, and execution run produced it.

Decision:
We establish the **Export Layer**.
- Exporting is no longer an ad-hoc action. It is a governed orchestration.
- The `ExportService` manages `ExportJobs`.
- The rule is strictly enforced: `Dataset -> Data View -> Insight -> Export`.
- Charts and Dashboards are prohibited from directly saving files to disk.

Consequences:
- An exported file becomes an audit-proof analytical asset. Every file generated by LightBI carries a traceable history back to the raw source data.
