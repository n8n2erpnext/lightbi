# LightBI Phase 24 - Export Foundation & Artifact Governance

**Date:** 2026-06-01

## New Architectural Decisions
- **ADR-047 (Export Architecture)**: Defined file generation as a strict, orchestrated backend process. Charts and Dashboards are prohibited from directly saving files to disk. All downloads must be requested via the `ExportService`.
- **ADR-048 (Export Artifact Model)**: Established the `ExportArtifact` to track generated files. This model guarantees absolute traceability; any file generated by LightBI carries a permanent lineage record linking it back to its source datasets and views.

## Rust Implementation (`lightbi-export`)
- Created `crates/lightbi-export` to govern file delivery.
- Modeled `ExportJob`, `ExportType` (`CSV`, `PDF`, `Excel`, `PNG`, `ProjectBundle`), and `ExportStatus`.
- Authored the `ExportArtifact` structure containing `ArtifactLineage` pointers.
- Authored the `ExportService` which will eventually act as the single funnel orchestrating generators (like a CSV Writer).
- Authored the `ExportRegistry` to keep a history of generated artifacts.

## Extensibility & Persistence
- Authored `migrations/20260601130000_export_foundation.sql` establishing SQLite tables: `export_jobs`, `export_artifacts`, and `artifact_lineage`.
- Injected the `ExportService` and `ExportRegistry` into the `ProjectContext`.
